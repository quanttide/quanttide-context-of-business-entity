# 意图·洞察·蓝图：三仓库分工

三个仓库分别回答三个问题，对应三种压力：

| 仓库 | 回答 | 缓解的压力 |
|------|------|----------|
| **intention**（意图） | 为什么做、什么不做 | 边界压力——知道什么不该操心 |
| **insight**（洞察） | 看到了什么、怎么判断 | 判断压力——有分析过的依据可循 |
| **roadmap**（蓝图） | 去哪里、怎么去 | 方向压力——知道下一步往哪走 |

## 日常流的循环

这三个仓库不是独立维护的，它们构成一个持续的循环：

1. 想到一个想法 → 记到日志
2. 判断属于哪个领域 → 更新对应的 intention/insight/roadmap
3. AI 根据更新后的内容去执行

## 压力的分流机制

- **当天想不清楚的事** → intention 划边界，告诉自己"这事现在不考虑"
- **想清楚了但不知道怎么下手** → roadmap 拆步骤，告诉自己"先从第一步开始"
- **做完了得出结论** → insight 沉淀下来，下次遇到类似问题不用重新想

压力不是被"解决"的，是被这个系统分流了。每一层承接一部分压力，剩下的交给下一层或者交给 AI。

## 实例：今天的命名迭代

今天 asset 模块经历了 `audit` / `evaluate` / `quality` / `status` 四个命名的反复修改。

这个过程其实走了一遍三仓库循环：

- **intention**：确定"结构合规"和"语义质量"是两件事，不应该塞在一个命令里
- **insight**：意识到边界不清楚不是因为命名没想好，而是问题本身就站在多个领域的交叉点上
- **roadmap**：把"以 profile 为事实源"写进 ROADMAP.md，拆出具体步骤
