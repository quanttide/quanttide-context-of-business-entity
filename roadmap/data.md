设计：带标注指令的纯文本块

文档结构保持不变（## RAW + ## EXTRACTED），但在 EXTRACTED 层里，AI生成的每一行都带上一个可被批量修改的标记前缀。你只需要改几个字符，就完成了批量标注。

核心标记体系（沿用你熟悉的Todo风格）：

标记 含义 你只需改这一个字符
[ ] AI生成，待确认 默认状态
[x] 你确认采纳/正确 把空格改成x
[-] 你确认废弃/错误 把空格改成-
[?] 你标记需要再议 把空格改成?
[~] 你修改了内容 改内容的同时改标记

—

从对齐到反馈之间的距离是什么呢。差了十万八千里吧...

AI读取时的逻辑

程序扫描文件时，只做一件事：对比标记状态，识别变更。

· [ ] → 跳过，未处理
· [x] → 提取内容，进入对应管道（情绪进健康模块，意图进执行云，模型进知识库）
· [-] → 记录为“已废弃”，用于后续模型训练（知道什么不该做）
· [?] → 进入“待讨论”队列，下次提醒你
· [~] → 这是关键：AI对比原文和你修改后的内容，把差异作为高质量反馈，更新自己的抽取模型

—

为什么这个设计符合你

1. 批量操作零负担：就是改几个字符。你用任何编辑器都能做，Ctrl+F 批量替换 [ ] 为 [x] 都行。
2. 一眼看出哪些没处理：[ ] 就是待办，剩下的都处理过了。
3. AI明确知道你的判断：不是模糊的“用户看过了”，而是精确到每一行的 采纳/废弃/修改/存疑。
4. 修改痕迹本身就是训练数据：[~] 标记的条目，天然形成了“AI版本 vs 人类版本”的对照集。
5. 完全兼容你现有的工作流：就是在你已经在做的 EXTRACTED 层上，加了最轻的一层标记语法。你之前说“todo文件标注已完成好用”，这就是它的直接延伸。

—

如果还需要更“批量”一点

如果你觉得逐行改还是太麻烦，可以加一个块级标记，一行控制整个块：

```markdown
## EXTRACTED [x]     <- 整块确认，所有子项默认采纳
```

或者

```markdown
### 行动意图 [-]
[ ] ...   <- 整块废弃，不用逐行看
```

这样你只需要在块标题旁加一个标记，就能批量处理整个块。AI识别到块级标记时，会自动应用到所有子项。

—

这就是你要的：Todo文件的灵魂，套上了结构化抽取的壳。极简、可批量、变更明确、AI友好。

## 实验：data 标注模块

将上述标记系统实现为一个可运行的 `src/data` 模块。

### 定位

- 输入：`think` 输出的 cognition.yaml（结构化认知要素）
- 输出：带标记的 markdown 文件，供用户批量确认
- 下游：确认后的数据回流到 `health`、`execute` 等模块

### 核心流程

```
think (认知提取) ──→ data (标注确认) ──→ execute (执行筛选)
                       ↓
                  health (情绪基线)
```

### 标注格式

```
### 情绪快照
[x] 主导情绪: 混合（疲惫+希望）
[ ] 强度: 中
[~] 关键词: 困惑, 方向感, 重构  ← 用户修改了内容

### 行动意图
[x] 让执行云先跑起来
[-] 砍掉已验证废弃的东西          ← 用户标记废弃
[?] 把QT的命挂上来                ← 待决策
```

### 标记含义

| 标记 | 含义 | AI 处理逻辑 |
|------|------|------------|
| `[ ]` | 待确认 | 跳过，未处理 |
| `[x]` | 已采纳 | 进入下游管道 |
| `[-]` | 已废弃 | 记录训练数据 |
| `[?]` | 待决策 | 进入待讨论队列 |
| `[~]` | 已修改 | 对比差异作为反馈 |

### 块级标记

支持在标题行使用块级标记批量控制：

```
### 行动意图 [x]     ← 整块采纳
### 情绪快照 [-]     ← 整块废弃
```
